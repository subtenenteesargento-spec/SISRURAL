2. Dispositivos de acesso — Fase B.
   - Registro por usuário + dispositivo.

3. Modo de segurança de dispositivo.
   - “Observação”: registra os aparelhos; Pendente ainda entra; Revogado não entra.
   - “Estrito”: Policial só entra em dispositivo Autorizado.
   - Administrador Geral ativa/desativa no painel.
   - Supervisão/Administração não são bloqueadas por essa regra para preservar a capacidade de gestão.

4. Redução de exposição no cliente.
   - Perfil Policial não assina coleções administrativas (usuários, dispositivos, auditoria, solicitações).
   - Visitas, ocorrências e propriedades em nuvem são consultadas somente pelo município do Policial.
   - Supervisão/Gerência mantém visão ampla da Companhia.

IMPORTANTE — SEGURANÇA REAL
O bloqueio de interface e dispositivo no JavaScript é uma camada de proteção, mas NÃO substitui regras do Firestore.
Além disso, a base antiga de propriedades de Casa Branca ainda existe de forma estática em js/mapa-ui.js por compatibilidade histórica.
Enquanto esses dados permanecerem em arquivos JavaScript hospedados publicamente, eles podem ser baixados diretamente sem passar pelo login.

PRÓXIMA ETAPA OBRIGATÓRIA PARA ENDURECIMENTO
A) Migrar a base estática de propriedades para Firestore.
B) Remover nomes/telefones/coordenadas de propriedades dos arquivos públicos do site.
C) Implantar regras Firestore por perfil e município no servidor.
D) Revisar entrega das fotos (Cloudinary URLs são públicas se a URL for conhecida).

Não publicar regras restritivas no Firestore sem antes migrar os documentos antigos e validar os perfis/UIDs, para evitar bloqueio do sistema.
